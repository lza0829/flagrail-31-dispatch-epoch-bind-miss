# 灰度轨

中文名：**灰度轨** · 前缀 `flagrail` · 端口 **6800 / 11800**

## 骨架

**开关版本入轨 → 分桶灰度下发 → 回读确认 → 失效/回滚互证**

皮：功能开关 / 配置灰度控制台。去皮是 **版本入轨 + 分桶下发 + 回读确认 + 命运互证**，不是配置 CRUD、不是 RBAC、不是发版审批闸。

领域：**基础设施** · 子方向：**中间件**

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6800
# 开关轨 → 入轨样例 → 分桶规 → 下发 → 回读样例 → 轨贯验 → 回滚样例
```

## 载荷纪元

版本键/版本号不变但载荷哈希变化时，默认走「纪元抬升」口径：

- 首次入轨写 `载荷纪元=1` 与 SHA-256 `载荷哈希`。
- 同版本键改载荷再提交：纪元自动 `+1`，响应明细可区分 `二次`、`二次成功`、`纪元变化`。
- 旧纪元下发票自动置 `已作废`，写 `作废旧钉` 列表与 `命运账(命运=作废)`；同票号可按新纪元/新哈希重钉。
- 下发票保存 `下发钉纪元/下发钉哈希`；请求显式带回旧纪元或旧哈希时返回 409，不静默钉旧。
- 回读保存 `所见纪元/回读所见哈希`；旧纪元确认默认记为 `旁置`，传 `"严格": true` 或站规设为拒绝时返回 409。
- `GET/POST /api/核证`、`/api/载荷纪元/核证` 返回 `{ 纪元, 载荷哈希, valid, ... }`；`POST /api/贯验` 自动化校验版本、钉票、回读哈希与作废命运。

可用夹具/自动化：

```bash
POST /api/装载/夹具?名=载荷纪元样例      # 改载荷→旧纪元回读旁置→新纪元重下发→新哈希确认
POST /api/装载/夹具?名=改载荷再提交
POST /api/装载/夹具?名=旧纪元回读
POST /api/装载/夹具?名=新纪元重下发
POST /api/装载/夹具?名=更新与下发并发    # 并发核证：生效票不得是新纪元标签+旧哈希
```

另一套正确性口径是「版本键载荷冻结」：请求体传 `"绑定策略": "冻结"`（或把站规 `载荷绑定策略` 设为冻结），已入轨载荷的二次修改直接 409，纪元不变。
